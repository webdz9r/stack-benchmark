# C

The bare-metal baseline, with no runtime, garbage collector or framework:

- **HTTP:** GNU **libmicrohttpd**. Its I/O threads only accept connections and
  move bytes.
- **SQLite:** the official **amalgamation**, compiled in with the same version
  and options as the Rust reference.
- **JSON input:** **yyjson**. JSON output is written by hand.
- **gzip:** **zlib**.

## Build and run

Needs a C11 compiler, `make`, `pkg-config` and `curl`, plus:

```sh
brew install libmicrohttpd yyjson                               # macOS
sudo apt install libmicrohttpd-dev libyyjson-dev zlib1g-dev     # Debian/Ubuntu
```

```sh
make                          # the first build downloads the SQLite amalgamation into vendor/
./seed 110000                 # optional: fake contacts
THREADS=4 ./server            # :7885
```

| Variable | Default | |
| --- | --- | --- |
| `DATABASE_PATH` | `data/address-book.db` | SQLite file |
| `BIND_ADDR` | `127.0.0.1:7885` | listen address |
| `STATIC_DIR` | `../../frontend/dist` | built frontend |
| `MIGRATIONS_DIR` | `../migrations` | shared migrations, read at runtime |
| `THREADS` | CPU count | the core budget: the number of worker threads, each with its own read connection (so also the reader count, `DB_READERS`), and the number of I/O threads |

## Threading (ARCH-11)

1. **I/O threads (libmicrohttpd):** accept connections, read requests and write
   responses.
2. **Cache hits:** a cacheable GET that's already in the response cache is
   answered right on the I/O thread, the way Rust's async handlers do.
3. **Everything else:** the I/O thread copies what the request needs, suspends
   the connection, and queues the request for one of `THREADS` worker threads.
   The worker runs the SQL, builds and gzips the reply, and resumes the
   connection.

An earlier version ran SQLite on the I/O threads. Under bursts of load, all of
them could be inside a query at once, and nobody accepted connections. That
caused connection resets at 6,000 users (499 failed requests when levels ran
back to back); with workers there are none.

## Layout

| File | |
| --- | --- |
| `src/main.c` | configuration, routing, request handling, startup and shutdown |
| `src/db.c` | connections, pragmas, migrations, the serialized writer, the write counter, WAL checkpoints |
| `src/repo.c` | the canonical SQL, writing JSON directly into a buffer |
| `src/validate.c` | request bodies (yyjson) and every validation rule |
| `src/cache.c` | response cache: 64 MiB LRU, 30 s TTL, 1 s staleness, shared misses, ETags |
| `src/http.c` | responses, gzip (level 6, 32 bytes and up), static files and the SPA fallback |
| `src/text.c` | UTF-8, Unicode whitespace trimming, lowercasing, the search tokenizer |
| `src/unicode_table.h` | Letter/Mark/Number code point ranges, generated by `scripts/gen_unicode.py` (`make unicode`) |
| `src/seed.c` | the deterministic seeder |

## Notes

- **SQLite build:** pinned to the same version the Rust reference bundles
  (`SQLITE_VERSION` in the Makefile), and compiled with FTS5, STAT4 and
  `SQLITE_DEFAULT_MEMSTATUS=0` (DB-2).
- **Statement reuse:** statements are prepared once per connection and reset
  right after use, so no read transaction stays open between requests.
- **Lowercasing:** labels are lowercased with `towlower`, which needs a UTF-8
  locale. The server selects `C.UTF-8`, or `en_US.UTF-8` if that's missing.
- **Framework-level behavior:**
  - a wrong method on a known path gets 405
  - a JSON body without a `Content-Type` is accepted
  - a body over 1 MiB gets 413
- **Static files** are read from disk on each request. The benchmark doesn't
  measure them.

## Optimizing

- **Never run SQLite on the libmicrohttpd I/O threads** (see Threading). With
  queries on the I/O threads, a burst of slow queries left no thread accepting
  connections, and clients saw resets at 6,000 users.
- **The listen backlog isn't the fix on macOS:** `kern.ipc.somaxconn` is 128
  and caps every backlog, so `MHD_OPTION_LISTEN_BACKLOG_SIZE 1024` changed
  nothing. The resets went away only when queries moved to worker threads.
- **Trade-off:** handing uncached requests to a worker costs a queue hop. The
  single-contact throughput test fell from ~91k to ~48k req/s, while the mixed
  load got much better (0 errors, p99 77 ms at 6,000 users). Cache hits are
  still answered on the I/O thread.
- The Makefile's SQLite flags keep `-O3` and `SQLITE_DEFAULT_MEMSTATUS=0`, and
  the amalgamation has no `SQLITE_ENABLE_MEMORY_MANAGEMENT`.
- **Tools:** macOS `sample <pid> 8`. See [`docs/optimizing.md`](../../docs/optimizing.md).
